# WorkBuddy 安装与运行

文档依据核对至 2026-10-26：[技能格式](https://open.workbuddy.cn/docs/skill)、[技能市场使用](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)、[收入变现](https://open.workbuddy.cn/docs/monetization)。客户端和平台要求可能变化，以实际版本及当前官方说明为准。

## 安装与首次使用

1. 下载仓库提供的 WorkBuddy 安装包。不要把 GitHub 的整个源码压缩包当作技能安装包。专用 ZIP 内只有一个 `tax-return-filler/` 根目录，根目录直接包含 `SKILL.md`，并保留运行脚本、模板和说明。
2. 在 WorkBuddy 技能页面选择「添加技能 → 上传技能」导入 ZIP，并确认技能已启用。界面名称以实际客户端为准。
3. 首次使用随包合成资料，输入：「使用纳税申报填表与复核，运行随包合成业务演示，将填写稿和复核报告保存到新的输出目录。」先确认脚本能运行、Excel 能打开、报告能查看，再处理已获授权的业务资料。

实际业务中，提供利润表、收入台账、预缴及必要专项资料，说明公司、申报期间和税种。Agent 读取资料后集中列出缺项，自行建立映射并执行程序；用户无需编辑 JSON 或逐格配置。输出为待会计复核的填写稿，不能据此声称已完成税务申报。

运行环境需要 Python 3.10+ 和 `requirements.txt` 指定的 openpyxl。环境检查及依赖安装见 [运行说明](runtime.md)，适用场景见 [业务工作流](business-workflows.md)。

## 安装包结构与升级

0.3.0 的资源采用平层布局：ZIP 中的资源路径最多为 `tax-return-filler/目录/文件`。模板、元数据和示例均直接放在 `assets/`，不再嵌套 `assets/forms/` 或 `assets/examples/`。专用打包器和分发检查会验证目录深度、必需资源、版本及文件哈希。

升级时先备份当前技能，按客户端支持的导入或编辑方式替换新包中的完整资源，并保留平台生成的安装元数据。不要仅修改版本号或只替换 `SKILL.md`。升级后回读版本、核对文件清单，再运行合成演示；确认升级成功且无需回退后，清理旧安装包和备份。

历史测试在 2026-10-26 的 macOS WorkBuddy 5.9.2 上完成；新客户端、Windows 和云端环境仍需分别验证。结果及边界见 [验证摘要](../research/verification-summary.md)。

## 数据与权限

运行脚本仅在指定资料和输出目录中读取、计算及写入文件，不主动联网。WorkBuddy 的对话、模型上下文和工具调用如何处理数据，由宿主配置及平台条款决定；不能因此承诺财务数据不出机。

处理真实资料前，确认企业允许在当前宿主环境处理这些文件。首次试用优先使用脱敏副本。不要在聊天或公开仓库中提供办税密码、验证码、真实客户账簿或账号凭证，也不要把资料转传到额外 OCR、检测或存储服务。

## 本地与云端分别验收

本地安装成功不证明付费或其他云端运行环境可用。目标环境应分别检查 Python 版本、依赖安装、附件读取、中文文件名、输出下载、文件隔离、运行限制以及数据保存和删除能力。

使用同一组合成资料比较本地与目标环境的结果，同时确认缺项、重复和币种冲突等异常会被阻断。记录实际环境版本、输入及输出哈希；只按验证过的环境与业务范围介绍兼容性。

收费、审核、托管和服务条款另按当前平台要求核实。程序测试、包结构检查、平台审核和真实会计业务验收是不同事项；本项目不提供税局登录、申报提交、签名、缴款或受理回执功能。

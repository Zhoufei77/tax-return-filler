# 纳税申报表填充助手：验收标准

版本：候选首版；制定日期：2026-10-26。各项当前状态默认“未验收”，只有实际证据可以改为通过。本文定义签收条件，不报告已取得成绩。

## 验收对象

WorkBuddy 从原始利润表、收入台账、预缴和专项资料自动取数，执行已核实业务规则，填写月度、季度、年度对应工作底稿或用户原有模板，输出来源和异常记录。经办人确认必要事实，不提前手算所有税额。支持表版与业务矩阵必须逐项验证，不能以一个模板通过推及全部税种。申报提交和缴税不在本产品验收范围；已实现的税务计算必须单独验收。

## 两个层级

**技术候选验收**：结构检查、确定性脚本测试和独立留出测试通过，可交付候选包供试点。没有真实主要任务时只能称“结构校验通过”；合成文件成功不能称真实业务验证。

**商业上市验收**：以下所有必须项均通过。缺少实际会计、客户材料、目标平台、付款证据等外部条件时，记录“未验证/未通过”，不能用开发者自评替代，也不能称商业已验证。

## 样本与盲测方法

1. 至少 2 位具备相关业务能力的实际会计参加，覆盖至少 10 个不同“企业×所属期”样本；同一个企业同一期间重复运行只算 1 个样本。覆盖至少 2 个不同源表结构及 2 个不同目标模板，并包含月、季、年使用情境或明确缩窄销售声明。
2. 经授权取得脱敏资料，保留会计复核所需的关联信息；不得为了脱敏破坏原始重复、期间或金额关系。真实与合成样本分开统计。
3. 会计先独立制作标准答案并封存，包含应填金额、取数范围、舍入规则、必需阻断及其原因。执行 Agent 不读取答案，完成后再比较；开发者不得边看答案边修留出样本。
4. 留出样本至少占真实样本 30%，不少于 3 个企业期；失败后可以修复，但必须增加新的未见留出样本，再完成关键回归。
5. 缺失、重复、跨期等例外可以用明确注入的合成副本补足；报告注入方式和预期，不将它们充作真实商业样本。

## 重大异常至少包括

| 异常 | 必须行为 |
| --- | --- |
| 缺文件、缺工作表、缺字段、关键金额为空或非数字 | 指出缺口，不能默默填零 |
| 主体混入或目标主体不一致 | 阻断并定位文件/记录；不能猜测归属 |
| 所属期缺失、来源期间混合、开票期与已确认业务期冲突 | 阻断有关取数；不能自动改期掩盖问题 |
| 同一文件重复输入、同一业务/发票编号重复且影响金额 | 识别并阻断或按预先确认的确定去重规则处理；不能静默双计 |
| 同一编号对应不同金额/内容 | 报冲突并阻断，不能任取一条 |
| 同名表头、模糊字段、目标单元格非法或多项写同一格 | 阻断不确定映射 |
| 公式只有缺失/过期缓存、宏或不支持结构影响取数 | 不使用未知结果继续填写 |
| 源文件或模板结构改变、复用映射不再匹配 | 提示变化并要求必要确认 |
| 不支持的跨期调整、税务分类、优惠或算税要求 | 明确说明未覆盖，交给会计判断，不生成肯定结论 |

异常检测必须根据输入可观察证据验收；没有主体或期间字段也没有用户确认时，不能声称已核验主体/期间。未提供未开票收入台账时，不能声称“已确认全部收入完整”。

## 操作数和计时口径

“一轮集中确认”指 Agent 汇总必要问题后，用户一次回答可使正常任务继续；连续追问多个字段要按实际轮数记录。文件选取、补资料、查看说明及手工改表都是用户操作；按键数可附录，但不能仅用对话轮数掩盖工作量。因真实重大异常而补资料可合理增加操作，应单列例外组。

总主动工时包含人完成工作的时间，不只统计脚本运行时间。首次设置及依赖安装单列，复用时不能漏掉准备及核对时间。工具等待时间另列；不得把会计手工预处理移到计时起点之前。减少比例为 `(手工主动工时－Skill 主动工时) / 手工主动工时`。

## 失败、复测与报告

金额错、重大异常漏拦、覆盖原文件、错误复用映射、谎称申报成功，任一项即拒绝本次签收；不得以其他项目得分抵消。修复后回归所有关键类别，并用新的留出样本验证。

最终报告逐项填写“通过/失败/未验证/不适用”、证据路径、执行日期、版本及签收人。不适用必须同步缩窄销售声明；缺外部资源只能记未验证。报告分别说明合成测试、独立留出、真实业务、Windows WorkBuddy 和付费试点的完成程度。
